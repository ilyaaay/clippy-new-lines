# clippy-new-lines

A filter for `cargo clippy` diagnostics: it only reports warnings and errors
that fall on lines changed in the current commit (staged changes). Pre-existing
warnings in untouched code do not block the commit.

The typical use case is a pre-commit hook that prevents new clippy warnings from
entering the repository without requiring you to fix the entire legacy codebase.

## Requirements

- Rust (edition 2024, stable toolchain);
- `git`;
- `cargo clippy`;
- the git repository root must be the Cargo workspace root;
- run from the repository root.

## Installation

```bash
cargo install --path .
```

Or run it without installing:

```bash
cargo run --quiet --
```

## Usage

The tool reads cargo JSON diagnostics from stdin, so it must be used in a pipe
with `--message-format=json`:

```bash
cargo clippy --all-targets --all-features --message-format=json \
  | clippy-new-lines
```

Important: use `pipefail`, otherwise `cargo clippy`'s exit status is lost and
the hook will pass even when compilation fails.

```bash
set -o pipefail

cargo clippy --all-targets --all-features --message-format=json \
  | clippy-new-lines
```

### Pre-commit hook

`.git/hooks/pre-commit`:

```bash
#!/usr/bin/env bash
set -euo pipefail

cargo clippy --all-targets --all-features --message-format=json \
  | clippy-new-lines
```

Make the file executable:

```bash
chmod +x .git/hooks/pre-commit
```

### What counts as "new code"

Changed lines are taken from `git diff --cached` (staged changes only, `*.rs`
files only, added/modified/copied/renamed).

A diagnostic is reported if its primary span overlaps one of the changed line
ranges. Diagnostics outside changed lines are discarded.

## Output and exit codes

- `0` — no new problems;
- `1` — clippy warnings/errors found on changed lines, or an internal error
  occurred (e.g. `git` could not be executed).

Reported problems are printed as:

```
  warning src/main.rs:12:5: unused variable: `x` [unused_variables]
```

Output is colored for terminals.

## Limitations

- Only staged changes are considered, but `cargo clippy` compiles the working
  tree. If the same `.rs` files have unstaged edits, line numbers may not match.
  Before committing, the working tree must match the index (or have no unstaged
  changes in Rust files).
- Only primary spans are checked. Diagnostics without a primary span and lints
  generated by macros may be missed.
- Only the targets cargo actually built are checked. Pass
  `--all-targets`/`--all-features` to cover tests, examples, and features.
- The tool does not replace `cargo clippy`; it only filters its output.
  Compilation errors in untouched code are not detected — use `pipefail` for
  that.

## How it works

1. `git diff --cached --name-only -z --diff-filter=ACMR -- '*.rs'` — list of
   staged Rust files.
2. For each file, `git diff --unified=0` hunk headers are parsed to obtain the
   changed line ranges.
3. Lines from stdin are parsed as cargo JSON messages
   (`reason == "compiler-message"`).
4. For each `warning`/`error` diagnostic, its primary span is checked; if it
   overlaps changed lines, the problem is printed and the process exits with
   code `1`.
